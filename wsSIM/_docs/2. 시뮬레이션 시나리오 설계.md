# SO-ARM101 Isaac Sim 제어 시나리오 설계

## 1. 문서 목적

이 문서는 상부 카메라의 객체 검출 결과를 이용해 Isaac Sim의 SO-ARM101을 이동시키는 전체 시나리오와 개발 요구사항을 정의한다. 각 과정에서 구현할 기능, 결정할 설정, 고려할 예외 및 현재 개발 진행도를 함께 관리한다.

진행 상태 표기는 다음과 같다.

- `[o]`: 구현 또는 검증 완료
- `[△]`: 미구현, 부분 구현 또는 추가 결정 필요
- `[x]`: 현재 조건에서 처리 불가

각 단계의 진행률은 해당 단계의 `[o] 항목 수 ÷ 전체 체크 항목 수`로 계산한다. 구현 난이도에 따른 가중치는 적용하지 않으므로 프로젝트 일정 진척률과는 다를 수 있다.

## 2. 시나리오 목표와 범위

### 2.1 목표

```text
객체 검출 정보 생성
→ 픽셀 좌표 해석
→ 로봇 좌표로 변환
→ FK 및 IK 계산
→ 액션 Goal 전송
→ 6축 관절 보간
→ Isaac Sim 로봇 이동
→ 목표 도달 확인
→ Z축 하강
→ 그리퍼 열기·닫기
→ 객체 작업 완료 판정
```

### 2.2 현재 구현 범위

```text
Mock Detection 생성
→ 첫 번째 객체 선택
→ 상대 XY 좌표 매핑
→ FK 및 위치 IK
→ MoveJoints Goal 전송
→ 6축 smoothstep 보간
→ Isaac Sim 이동
```

### 2.3 현재 미구현 범위

```text
실제 JointState 기반 목표 도달 판정
→ bbox 기반 객체 허용 반경 판정
→ Z축 하강
→ 그리퍼 열기
→ 그리퍼 닫기
→ 객체 작업 완료 판정
→ 여러 객체 순차 처리
→ 실패 시 현재 주기 폐기 및 다음 주기 재개
```

### 2.4 전제 및 제한사항

- 상부 카메라가 작업 평면을 내려다보는 환경을 가정한다.
- 현재는 실제 카메라와 YOLO 대신 `MockDetector`가 임의의 Detection을 생성한다.
- 객체 데이터는 중심 픽셀 좌표, bbox, class 및 confidence를 포함한다.
- 객체의 작업 높이 Z는 고정값으로 사용할 예정이지만 아직 수치를 정하지 않았다.
- 현재 픽셀 매핑은 캘리브레이션 결과가 아닌 테이블 크기 기반 임시 변환이다.
- 현재 IK는 XYZ 위치만 계산하며 end-effector orientation을 제한하지 않는다.
- 실제 물체 파지는 수행하지 않고 그리퍼 동작 완료를 가상 픽업으로 간주할 예정이다.

## 3. 전체 시스템 구조

```text
detector.py / MockDetector
  - Mock Detection2DArray 생성
  - /topcam/position_maker 발행
        |
        v
move_joints_action_client.py
  - 첫 번째 객체 선택
  - 픽셀 → 상대 XY 이동량 변환
  - 현재 JointState 기반 FK
  - 목표 XYZ 기반 IK
        |
        | /move_joints_action send_goal
        v
move_joints_action_server.py
  - Goal 검증
  - 6축 5차 smoothstep 보간
  - /so_arm101/joint_command 발행
        |
        v
Isaac Sim Action Graph / Articulation Controller
        |
        | /so_arm101/joint_states
        v
Action Client 및 Action Server
```

### 3.1 노드별 책임

| 구성 요소 | 책임 | 책임에서 제외되는 항목 |
|---|---|---|
| `MockDetector` | Mock Detection 생성 및 토픽 발행 | 좌표 변환, IK, 로봇 명령 |
| Action Client | 입력 검증, 좌표 매핑, FK/IK, 작업 순서, Goal 전송 | Isaac Sim JointCommand 직접 발행 |
| Action Server | 관절 Goal 검증, 보간, JointCommand 발행, 관절 이동 결과 | 객체 의미 해석, 픽셀 좌표 처리 |
| Isaac Sim | 로봇 물리 시뮬레이션, JointState 발행, 관절 명령 실행 | 객체 작업 성공 정책 |
| `kinematics.py` | URDF 기반 FK와 위치 IK | 경로 계획, orientation 및 충돌 검사 |

### 3.2 ROS 2 인터페이스

| 구분 | 이름 | 타입 | 발행 | 구독 |
|---|---|---|---|---|
| Topic | `/topcam/position_maker` | `vision_msgs/Detection2DArray` | MockDetector | Action Client |
| Topic | `/so_arm101/joint_states` | `sensor_msgs/JointState` | Isaac Sim | Action Client, Action Server |
| Topic | `/so_arm101/joint_command` | `sensor_msgs/JointState` | Action Server | Isaac Sim |
| Action | `/move_joints_action` | `so_arm101_interface_pkg/action/MoveJoints` | Action Server | Action Client |

## 5. 단계별 개발 요구사항

### 5.1 객체 검출 데이터 생성 — 4/6 (67%)

목적은 실제 YOLO가 없어도 후속 노드의 입력 처리 과정을 반복 시험할 수 있는 Detection 데이터를 제공하는 것이다.

요구사항:

- [o] `MockDetector` ROS 2 노드 구현
- [o] 중심 좌표, bbox, class 및 confidence 생성
- [o] `Detection2DArray` 메시지 구성
- [o] `/topcam/position_maker` 주기 발행 및 `interval` 파라미터 제공
- [△] 실제 YOLO Detector 입력으로 교체할 수 있는 인터페이스 확정
- [△] 이미지 또는 카메라 timestamp와 Detection의 동기화

고려사항:

- Detection ID가 주기 사이에서도 객체를 식별할 수 있어야 하는지 결정해야 한다.
- 실제 Detector로 교체해도 Action Client의 입력 메시지 형식은 유지하는 편이 단순하다.
- Mock 데이터 범위가 실제 카메라 해상도와 bbox 규칙을 위반하지 않아야 한다.

완료 조건:

- 설정한 주기로 유효한 `Detection2DArray`가 발행되고 Action Client가 메시지를 수신한다.

### 5.2 Detection 검증 및 객체 선택 — 3/7 (43%)

목적은 잘못된 객체 데이터가 좌표 계산과 로봇 이동으로 이어지지 않도록 입력을 검증하고 작업할 객체를 선택하는 것이다.

요구사항:

- [o] 빈 Detection 배열 무시
- [o] 객체의 `results`가 비어 있으면 무시
- [o] 배열의 첫 번째 객체 선택
- [△] confidence `0.85` 미만 객체 필터링
- [△] bbox 크기와 중심 좌표 유효성 검사
- [△] 이미지 범위를 벗어난 좌표 처리
- [△] 중복 ID와 오래된 Detection 처리

고려사항:

- 현재는 첫 번째 객체만 사용하므로 전달 순서가 곧 작업 우선순위가 된다.
- 유효하지 않은 첫 객체를 건너뛰고 다음 객체를 사용할지 전체 주기를 폐기할지 결정해야 한다.
- confidence와 class 우선순위는 향후 경로 최적화 정책과 분리해야 한다.

완료 조건:

- 유효한 객체만 좌표 변환 단계로 전달되고, 제외된 객체의 이유를 로그 또는 상태로 확인할 수 있다.

### 5.3 픽셀 좌표와 로봇 좌표 매핑 — 5/10 (50%)

목적은 이미지의 bbox 중심 `(u, v)`를 로봇이 사용할 수 있는 좌표로 변환하는 것이다.

현재 임시 설정:

```text
이미지 크기: 640 × 480
이미지 위쪽: World +X
이미지 왼쪽: World +Y
테이블 X 크기: 0.8085078 m
테이블 Y 크기: 1.1356210 m
```

```python
robot_x_offset = (240 - pixel_y) * (0.8085078 / 480)
robot_y_offset = (320 - pixel_x) * (1.1356210 / 640)
```

요구사항:

- [o] 입력 이미지 크기와 영상 좌표계 정의
- [o] 상부 카메라 영상과 World XY 축 방향 확인
- [o] 테이블 Mesh Extent와 Scale을 반영한 크기 계산
- [o] 현재 end-effector 기준 상대 XY 이동량 계산
- [o] 초기 시험용 축별 `±0.05 m` 제한
- [△] 카메라 좌표에서 로봇 `base_link`까지의 절대 변환
- [△] 고정 작업 높이 Z와 객체 위 접근 높이 결정
- [△] 그리퍼가 아래를 향하는 고정 orientation 결정
- [△] 작업영역 밖 목표의 거부 또는 clipping 정책
- [△] bbox 픽셀 크기를 실제 허용 반경으로 변환

고려사항:

- 현재 매핑은 상대 이동이므로 Detection을 반복 처리하면 이동량이 누적된다.
- 카메라가 이동하거나 회전하면 현재 비례식은 사용할 수 없다.
- 축별 clipping을 적용하면 대각선 실제 이동거리는 `0.05 m`보다 커질 수 있다.

완료 조건:

- 이미지의 대표 위치와 로봇 좌표의 대응을 검증하고, 작업영역 안에서 재현 가능한 목표 Pose를 만든다.

### 5.4 로봇 모델 및 FK/IK — 5/9 (56%)

목적은 현재 관절 상태와 목표 end-effector 위치 사이를 변환하는 것이다.

요구사항:

- [o] SO-ARM101 URDF와 STL을 description 패키지로 구성
- [o] `base_link`에서 `gripper_frame_link`까지 관절 체인 구성
- [o] 현재 관절값의 FK 계산
- [o] 목표 XYZ의 위치 IK 계산
- [o] URDF 관절 제한값 적용 및 gripper를 팔 IK에서 제외
- [△] 고정 end-effector orientation을 포함한 IK
- [△] 자기 충돌 및 환경 충돌 검사
- [△] 작업영역과 IK 가능 여부 사전 검사
- [△] URDF와 Isaac Sim의 관절 방향 및 영점 일치 검증

고려사항:

- 위치만 같은 여러 관절 해 중 현재 자세에서 가까운 해를 선택해야 한다.
- IK 해가 있어도 이동 경로 중 충돌하거나 관절 제한에 가까울 수 있다.
- URDF와 Isaac Sim의 영점 또는 축 방향이 다르면 계산상 성공한 IK가 다른 자세를 만든다.

완료 조건:

- 대표 목표 Pose들에 대해 IK가 관절 제한 안에서 계산되고 FK로 재검증했을 때 허용 위치 오차를 만족한다.

### 5.5 액션 클라이언트와 Goal 관리 — 7/9 (78%)

목적은 Detection을 작업 명령으로 변환하고 Action Server에 실행을 요청하는 것이다.

요구사항:

- [o] Detection 및 JointState 토픽 구독
- [o] 첫 번째 객체의 bbox 중심 좌표 해석
- [o] 현재 JointState를 이용한 FK 시작 자세 계산
- [o] 매핑 결과를 반영한 목표 XYZ 생성
- [o] IK 결과와 현재 gripper 값을 6축 Goal로 구성
- [o] `send_goal_async()`로 `MoveJoints` Goal 전송
- [o] Goal 실행 중 새 Detection 무시 및 result 수신 후 해제
- [△] 객체별 상태 머신과 단계별 Goal 관리
- [△] 여러 객체 목록 보관 및 순차 실행

고려사항:

- 현재 `moving` 플래그는 단일 Goal 중복 방지만 담당한다.
- Goal 거부, IK 실패 및 결과 실패를 객체 작업 실패 상태로 연결해야 한다.
- Z축 하강과 gripper 동작은 별도 Goal로 순서대로 실행해야 한다.

완료 조건:

- 하나의 객체 작업에 필요한 모든 Goal을 상태 순서대로 보내고 각 결과에 따라 다음 상태 또는 실패 상태로 전이한다.

### 5.6 액션 서버와 관절 이동 — 8/12 (67%)

목적은 관절 목표값을 검증하고 Isaac Sim에 부드러운 관절 명령을 전달하는 것이다.

요구사항:

- [o] Goal의 관절 이름, 위치 개수 및 duration 검증
- [o] 실제 JointState를 보간 시작점으로 사용
- [o] 6축을 동일 진행률로 동시 보간
- [o] 5차 smoothstep 적용
- [o] `/so_arm101/joint_command`에 `50 Hz` 발행
- [o] feedback에 실제 JointState와 시간 기반 진행률 제공
- [o] result에 반환 시점의 실제 JointState 제공
- [o] `MultiThreadedExecutor`와 분리된 콜백 그룹 적용
- [△] 관절별 위치 허용오차 결정 및 실제 목표 도달 판정
- [△] 목표 범위 유지 시간 또는 연속 확인 횟수 결정
- [△] JointState 수신 timeout과 전체 이동 timeout
- [△] 취소 시 현재 자세 유지 명령

고려사항:

- 현재 `success=True`는 목표 도달이 아니라 보간 명령 발행 완료를 의미한다.
- 시간 진행률과 실제 이동 진행률은 다를 수 있다.
- 여러 Goal이 들어올 때 거부, 대기 또는 교체 정책을 명시해야 한다.

완료 조건:

- 실제 관절값이 허용오차 범위에 안정적으로 들어온 경우에만 성공하고, timeout과 취소를 구분해 반환한다.

### 5.7 Isaac Sim 연동 — 7/8 (88%)

목적은 ROS 2 JointCommand가 올바른 SO-ARM101 Articulation에 단독으로 적용되도록 구성하는 것이다.

요구사항:

- [o] URDF를 USD로 import
- [o] USD import의 Base Type을 `Fixed`로 설정
- [o] 각 구동 Joint의 Drive 값 설정
- [o] `/so_arm101/joint_states` 발행 확인
- [o] `/so_arm101/joint_command`를 Articulation Controller에 연결
- [o] 중복 제어 Action Graph로 발생한 관절 떨림 원인 제거
- [o] 6축 보간 명령의 부드러운 이동 확인
- [△] 정상 Action Graph의 노드·연결·설정 캡처 및 재현 문서 작성

Joint Drive 설정:

```text
Max Force = 10000
Stiffness = 100000
Damping = 1000
```

고려사항:

- 동일 Articulation을 두 개의 그래프가 제어하면 목표 자세와 초기 자세가 번갈아 적용되어 떨릴 수 있다.
- `jointNames`와 `positionCommand` 배열의 길이 및 순서가 일치해야 한다.
- USD를 다시 import하면 Base Type과 Drive 값이 초기화될 수 있다.

완료 조건:

- 새 환경에서도 문서화된 설정만으로 로봇을 재구성하고 동일한 6축 이동을 재현할 수 있다.

### 5.8 객체 접근 및 작업 완료 — 1/7 (14%)

목적은 단순 관절 이동이 아니라 객체 하나의 가상 픽업 절차 전체를 완료하는 것이다.

예정 상태:

```text
MOVE_ABOVE_OBJECT
→ CHECK_TARGET_REGION
→ MOVE_DOWN
→ OPEN_GRIPPER
→ CLOSE_GRIPPER
→ OBJECT_COMPLETE
```

요구사항:

- [o] 계산한 XY 목표 방향으로 로봇 이동
- [△] 실제 관절 상태 기반 접근 위치 도달 판정
- [△] FK로 계산한 end-effector와 객체 중심의 XY 허용 반경 판정
- [△] Z축 하강 Pose 생성 및 이동
- [△] gripper 열림 관절값 Goal 실행
- [△] gripper 닫힘 관절값 Goal 실행
- [△] 모든 단계 성공 후 `OBJECT_COMPLETE` 판정

고려사항:

- 관절 이동 완료와 객체 작업 완료는 서로 다른 판정이다.
- 단순히 Goal을 발행했거나 duration이 끝난 것만으로 완료 처리하면 안 된다.
- gripper는 실제 파지 여부가 아니라 열림·닫힘 관절 도달로 가상 성공을 판단한다.

완료 조건:

- 접근, 허용 반경, 하강, 열기 및 닫기의 모든 결과가 성공한 경우에만 객체 하나를 완료 처리한다.

### 5.9 여러 객체와 작업 주기 — 1/7 (14%)

목적은 한 Detection 주기에 포함된 여러 객체를 정해진 정책대로 처리하는 것이다.

요구사항:

- [△] 유효 객체 목록 생성
- [△] 전달된 순서대로 객체 처리
- [△] 한 객체 완료 후 다음 객체로 전이
- [△] 모든 객체 완료 후 현재 주기 종료
- [o] Goal 실행 중 새 Detection 무시
- [△] 실행 중 새 Detection을 무시하거나 최신 하나만 보관하는 정책 확정
- [△] 경로 최적화 인터페이스 분리

고려사항:

- 초기 구현은 최적화 없이 전달 순서를 사용한다.
- 작업 중 객체 목록을 변경하면 좌표 기준과 완료 상태가 불명확해질 수 있다.
- 향후에는 현재 위치, 전체 이동거리, confidence 또는 class 우선순위를 적용할 수 있다.

완료 조건:

- 한 주기의 객체 목록이 실행 중 변경되지 않고, 모든 객체가 지정 순서대로 한 번씩 처리된다.

### 5.10 실패·취소·복구 — 1/8 (13%)

목적은 현재 작업을 안전하게 중단하고 다음 명령을 받을 수 있는 상태로 복구하는 것이다.

요구사항:

- [o] Action Server가 취소 요청을 수락하고 보간 반복 중단
- [△] 취소 시 실제 현재 자세 유지 명령
- [△] IK 실패, Goal 거부 및 timeout의 실패 결과 구분
- [△] JointState 수신 중단 감지
- [△] 현재 객체 실패 시 남은 객체 폐기
- [△] 실패한 객체의 자동 재시도 여부 확정
- [△] 다음 Detection 주기 대기 상태로 복귀
- [△] 노드 종료 시 실행 중 Goal 정리

고려사항:

- 실패 후 안전 자세로 복귀할지 현재 자세를 유지할지 결정해야 한다.
- 취소 요청 자체가 실패하거나 응답하지 않는 경우의 timeout이 필요하다.
- 이전 주기의 실패 객체가 다음 Detection에 다시 포함되면 새 작업으로 볼지 정해야 한다.

완료 조건:

- 각 실패 원인이 구분된 결과로 기록되고, 남은 명령을 폐기한 뒤 새 주기를 정상 수신한다.

### 5.11 시험 및 검증 — 6/11 (55%)

목적은 개별 계산, ROS 인터페이스 및 Isaac Sim 통합 동작을 단계별로 재현하는 것이다.

요구사항:

- [o] description 패키지와 URDF 구조 검사
- [o] 픽셀 좌표 매핑 단위 테스트
- [o] FK 및 위치 IK 단위 테스트
- [o] MockDetector에서 Action Client까지 메시지 수신 확인
- [o] Action Server에서 Isaac Sim까지 6축 보간 이동 확인
- [o] 단일 축 시험으로 Action Graph 문제 분리
- [△] 실제 JointState 기반 성공 판정 시험
- [△] timeout 시험
- [△] 액션 취소 및 자세 유지 시험
- [△] 객체 하나의 전체 작업 통합 시험
- [△] 여러 객체 및 중간 실패 주기 시험

고려사항:

- 단위 테스트 성공과 Isaac Sim 물리 동작 성공을 구분해 기록해야 한다.
- Action Graph와 USD 설정도 시험 환경의 일부로 버전 관리하거나 문서화해야 한다.
- 성공뿐 아니라 잘못된 입력과 실패 경로를 의도적으로 시험해야 한다.

완료 조건:

- 새 워크스페이스와 새 Isaac Sim Stage에서 빌드부터 전체 객체 작업까지 동일하게 재현된다.

## 6. 객체 하나의 목표 동작

```text
1. Detection 수신 및 유효성 확인
2. 객체 중심 픽셀을 로봇 좌표로 변환
3. 고정 Z와 하향 orientation을 적용한 접근 Pose 생성
4. 접근 Pose의 IK 계산
5. MoveJoints Goal 전송
6. 실제 JointState 기반 관절 도달 확인
7. FK 기반 객체 XY 허용 반경 확인
8. Z축 하강 Pose 생성 및 이동
9. gripper 열기 및 도달 확인
10. gripper 닫기 및 도달 확인
11. 객체 작업 완료
```

객체 작업 완료 조건:

```text
접근 관절 도달
AND bbox 기반 XY 허용 반경 만족
AND Z축 하강 관절 도달
AND gripper 열림 위치 도달
AND gripper 닫힘 위치 도달
```

## 7. 주기 단위 목표 동작

```text
1. 새 Detection 배열 수신
2. 유효 객체 필터링
3. 전달 순서대로 작업 목록 생성
4. 첫 번째 객체 작업 실행
5. 성공하면 다음 객체 실행
6. 모든 객체가 성공하면 현재 주기 완료
7. 어느 단계에서든 실패하면 현재 Goal 취소
8. 현재 주기의 남은 객체 폐기
9. 다음 Detection 주기 대기
```

## 8. 우선 개발 순서

1. 실제 JointState 기반 관절 목표 도달 판정
2. 관절 허용오차, 안정 유지 횟수 및 timeout 결정
3. 고정 작업 Z, 접근 높이, 하강 거리 및 orientation 결정
4. bbox 기반 XY 허용 반경 계산
5. `MOVE_DOWN → OPEN_GRIPPER → CLOSE_GRIPPER` 상태 전이
6. 객체 하나의 전체 완료 판정
7. 여러 객체 순차 처리
8. 실패 시 현재 주기 폐기와 다음 주기 복귀
9. 정상 Isaac Sim Action Graph 설정 문서화

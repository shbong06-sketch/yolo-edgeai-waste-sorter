## 1. 작업 목표

객체 검출 결과의 이미지 좌표를 액션 클라이언트에서 로봇 좌표와 관절 좌표로 변환하고, 액션 서버가 받은 6축 목표 관절값을 Isaac Sim에 부드럽게 전달하는 기본 흐름을 구성한다.

```text
detector.py
→ Detection2DArray 발행
→ move_joints_action_client.py
→ 픽셀 좌표 매핑 및 IK 계산
→ MoveJoints Goal 전송
→ move_joints_action_server.py
→ 관절 목표 보간
→ /so_arm101/joint_command 발행
→ Isaac Sim 로봇 이동
```

### 2.3 Mock 객체 검출 노드

- `detector.py`가 실제 YOLO 대신 임의의 객체 검출 결과를 주기적으로 생성하도록 구성했다.
- 검출 데이터는 `vision_msgs/Detection2DArray` 형식으로 `/topcam/position_maker` 토픽에 발행한다.
- detector는 검출 정보 발행만 담당하고 좌표 매핑과 IK는 수행하지 않도록 역할을 분리했다.
- 이미지 크기는 `640 × 480`으로 사용한다.
- 객체는 전달받은 순서대로 처리하며 우선순위 최적화는 이후 작업으로 남겼다.

### 2.4 이미지 좌표와 로봇 좌표 매핑

- Isaac Sim 상부 카메라 화면을 기준으로 축 방향을 확인했다.

```text
World +X = 이미지 위쪽, 12시 방향
World +Y = 이미지 왼쪽, 9시 방향
```

- Shop Table의 Mesh Extent와 `Scale:unitsResolve = (0.01, 0.01, 0.01)`을 반영했다.

```text
테이블 X 크기 = 0.8085078 m
테이블 Y 크기 = 1.1356210 m
```

- 현재 임시 매핑식은 다음과 같다.

```python
robot_x_offset = (240 - pixel_y) * (0.8085078 / 480)
robot_y_offset = (320 - pixel_x) * (1.1356210 / 640)
```

- 초기 이동 시험의 안전 범위를 위해 각 축의 이동 오프셋을 최대 `±0.05 m`로 제한했다.
- 현재 매핑 결과는 절대 좌표가 아니라 현재 end-effector 위치에 더하는 상대 이동량이다.

### 2.5 액션 클라이언트 단순화 및 IK

- `move_joints_action_client.py`가 검출 메시지를 받으면 첫 번째 객체를 처리하도록 단순화했다.
- 액션 클라이언트의 주요 동작은 다음과 같다.

```text
첫 번째 Detection 선택
→ bbox 중심 픽셀 좌표 추출
→ XY 상대 이동량 계산
→ 현재 JointState로 FK 계산
→ 목표 XYZ 생성
→ 5개 팔 관절 IK 계산
→ 현재 gripper 값을 추가
→ 6축 MoveJoints Goal 전송
```

- URDF 기반 FK와 위치 IK 계산을 위해 `kinematics.py`를 추가했다.
- 현재 IK는 end-effector의 XYZ 위치만 계산하며 orientation과 충돌은 고려하지 않는다.
- 액션 클라이언트는 Goal을 전달하는 동안 중복 Goal을 보내지 않도록 이동 상태를 관리한다.

### 2.6 액션 서버의 다중 스레드 실행 구조

- `move_joints_action_server.py`에 `MultiThreadedExecutor(num_threads=2)`를 적용했다.
- 액션 실행 콜백과 JointState 수신 콜백을 서로 다른 `MutuallyExclusiveCallbackGroup`으로 분리했다.
- 액션 실행 중 대기 시간이 있어도 다른 스레드에서 최신 JointState를 계속 받을 수 있도록 했다.
- 두 콜백이 공유하는 최신 JointState는 `threading.Lock`으로 보호했다.
- 취소 요청을 받을 수 있도록 `CancelResponse.ACCEPT`를 적용했다.

### 2.7 6축 관절 보간 이동

- 액션 서버가 Goal의 관절 이름, 관절 좌표 개수, 이동시간을 검증하도록 했다.
- Isaac Sim의 최신 JointState를 이동 시작점으로 사용한다.
- 6개 관절을 각각 따로 움직이는 것이 아니라 동일한 진행률로 동시에 이동시킨다.
- 명령 발행 주기는 `50 Hz`로 설정했다.
- 전체 단계 수는 다음과 같이 계산한다.

```python
total_steps = ceil(duration_seconds * 50)
```

- 각 단계의 관절 좌표는 다음 5차 smoothstep 보간으로 계산한다.

```python
progress = step / total_steps
alpha = 10 * progress**3 - 15 * progress**4 + 6 * progress**5
command = start + alpha * (target - start)
```

- 이 보간을 통해 시작과 종료 구간의 속도 및 가속도를 낮춰 급격한 출발과 정지를 줄였다.
- 각 단계에서 계산한 6축 좌표를 `/so_arm101/joint_command`로 발행한다.
- 실제 `/so_arm101/joint_states` 값을 액션 feedback과 result에 넣도록 구성했다.

### 2.8 단일 축 진단 코드

- 떨림 원인을 분리하기 위해 `test_one_axis()` 콜백을 추가했다.
- `axis_index`를 `0~5` 중 하나로 지정하면 해당 관절 이름과 좌표 하나만 한 번 발행할 수 있다.
- 단일 축에서도 떨림이 발생하는 것을 확인하여 6축 동시 보간 자체가 원인이 아님을 확인했다.
- 현재 액션 서버의 실제 실행 콜백은 다시 6축 보간 함수인 `execute_callback`에 연결되어 있다.
- `test_one_axis()`는 이후 진단을 위해 남겨둔 상태다.

## 4. 이슈 목록

### 4.1 해결된 이슈

#### 이슈 1: 6축 이동 시 로봇이 심하게 떨림

- 증상:
  - 보간 명령을 보내면 로봇이 목표 방향으로 움직였다가 이전 자세로 되돌아가는 동작을 반복했다.
  - `/so_arm101/joint_states`에서도 보간 위치와 초기 위치가 번갈아 관찰됐다.
- 초기 의심:
  - 목표 관절값 오류
  - 관절 순서 불일치
  - 6축 동시 보간 문제
  - 명령 발행 주기 문제
- 확인 과정:
  - URDF 관절 제한값과 목표값 비교
  - Isaac Sim JointState의 관절 이름과 순서 확인
  - 6축 동시 이동을 단일 축 명령으로 변경해 시험
  - Articulation Controller 입력의 관절 이름과 위치값 확인
- 원인:
  - ROS 2 액션 서버의 보간 코드가 아니라 Isaac Sim의 Action Graph 구성 문제였다.
- 결과:
  - Action Graph 문제를 수정한 후 동일한 6축 보간 명령으로 부드럽게 이동하는 것을 확인했다.
- 보완 필요:
  - 어떤 Action Graph 노드 또는 연결을 수정했는지 정확한 설정을 별도로 기록해야 한다.

#### 이슈 2: 기존 단계 반복이 실제 보간으로 동작하지 않음

- 증상:
  - 이전 서버는 20단계 반복문이 있었지만 매 단계마다 최종 목표값을 그대로 발행했다.
- 원인:
  - 단계별 중간 관절값 계산이 없었다.
- 조치:
  - 현재 JointState를 시작점으로 사용하고 5차 smoothstep으로 중간 좌표를 계산하도록 변경했다.

#### 이슈 3: 액션 실행 중 JointState 콜백 처리 가능성

- 증상:
  - 단일 스레드 실행기에서 액션 콜백이 `time.sleep()`을 수행하면 JointState 콜백이 지연될 수 있었다.
- 조치:
  - `MultiThreadedExecutor`와 분리된 콜백 그룹을 적용했다.
  - 공유 JointState에 Lock을 적용했다.

#### 이슈 4: 액션 클라이언트 코드 복잡도

- 증상:
  - 좌표 매핑, IK, 큐 처리, 검증 및 로그가 한꺼번에 포함되어 흐름 확인이 어려웠다.
- 조치:
  - 첫 번째 Detection을 받아 좌표 매핑, IK, Goal 전송만 수행하는 기본 흐름으로 단순화했다.

#### 이슈 5: shoulder_pan 축이 움직이지 않음

- 증상:
  - Isaac Sim의 Articulation Controller에 축 이름과 목표값이 들어와도 `shoulder_pan`이 움직이지 않았다.
- 조치:
  - URDF 로봇 모델을 USD로 다시 import했다.
  - USD import 옵션의 Base Type을 `Fixed`로 설정했다.
  - 각 구동 Joint에 아래 Drive 값을 설정했다.

```text
Max Force = 10000
Stiffness = 100000
Damping = 1000
```

### 4.2 남은 이슈 및 후속 작업

#### 이슈 6: 액션 성공 판정이 실제 목표 도달을 보장하지 않음

- 현재는 지정된 시간 동안 명령 발행을 완료하면 `success=True`를 반환한다.
- 실제 관절값이 목표 허용오차 안에 들어왔는지 확인하지 않는다.
- 후속 작업:
  - 관절별 위치 허용오차 설정
  - 실제 JointState와 목표값 비교
  - 일정 횟수 또는 일정 시간 동안 허용오차 안에 유지됐을 때 성공 처리
  - 목표 미도달 timeout과 실패 결과 처리

#### 이슈 7: 취소 시 정지 및 자세 유지 정책 미확정

- 현재 취소 요청 시 보간 반복은 종료하지만 별도의 자세 유지 명령은 보내지 않는다.
- 취소 순간의 실제 관절값을 다시 명령할지 결정해야 한다.

#### 이슈 8: 동시에 여러 Goal이 들어오는 경우의 정책 미확정

- 현재 액션 콜백 그룹은 동시에 실행되는 액션을 제한하지만 Goal 거부, 대기 또는 교체 정책은 명시적으로 구현하지 않았다.
- 초기 단계에서는 실행 중 새 Goal을 거부하는 방식이 단순하다.

#### 이슈 9: 픽셀 좌표 매핑이 임시 상대 좌표 방식임

- 현재 카메라 캘리브레이션과 TF를 사용하지 않는다.
- 카메라 픽셀과 로봇 base frame 사이의 정확한 절대 변환이 필요하다.
- 고정 작업 높이 Z와 end-effector orientation도 확정해야 한다.

#### 이슈 10: IK 제한사항

- 현재 IK는 XYZ 위치만 대상으로 한다.
- 그리퍼가 아래를 향하도록 하는 orientation 제약이 없다.
- 자기 충돌, 환경 충돌 및 경로상의 충돌을 검사하지 않는다.
- IK 실패와 작업영역 밖 목표에 대한 사용자 수준의 실패 처리가 더 필요하다.

#### 이슈 11: 반복 검출 메시지와 작업 주기 관리

- detector가 주기적으로 새 Detection을 발행한다.
- 현재 작업 중 새 메시지를 무시할지, 최신 메시지 하나를 보관할지 정책을 확정해야 한다.
- 한 객체 작업 실패 시 현재 주기의 나머지 객체를 폐기하고 다음 검출 주기를 기다리는 정책을 구현해야 한다.

#### 이슈 12: 객체 작업 완료 절차 미구현

- 현재는 목표 위치로 로봇을 이동시키는 단계까지만 검증했다.
- 다음 기능이 남아 있다.

```text
객체 중심 허용 반경 확인
→ Z축 소폭 하강
→ 그리퍼 열기
→ 그리퍼 닫기
→ 객체 작업 완료 처리
```

#### 이슈 13: Action Graph 설정 기록 필요

- 오늘 떨림 문제의 직접 원인은 Action Graph였다.
- 같은 문제가 재발하지 않도록 다음 정보를 문서화할 필요가 있다.

```text
사용한 Action Graph 경로와 이름
ROS2 Subscribe Joint State 연결 구조
Articulation Controller의 targetPrim 또는 robotPath
execIn 연결
jointNames와 positionCommand 연결
비활성화하거나 수정한 중복 제어 그래프
관절 Drive 설정
USD import Base Type = Fixed
Joint Drive Max Force = 10000
Joint Drive Stiffness = 100000
Joint Drive Damping = 1000
```

## 5. 현재 코드 상태

- 액션 서버 실행 콜백: `execute_callback`
- 이동 방식: 6축 동시 5차 보간
- 명령 주기: `50 Hz`
- 실행기: `MultiThreadedExecutor(num_threads=2)`
- 관절 상태 공유: `threading.Lock`
- 진단용 함수: `test_one_axis`
- Python 소스 변경 반영 방식: `colcon build --symlink-install` 이후 파일 저장 및 실행 노드 재시작

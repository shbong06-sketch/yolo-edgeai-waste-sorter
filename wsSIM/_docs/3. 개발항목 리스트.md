## 1. URDF 로봇 모델

### 완료된 작업

- [o] 원본 `trs_so101`에서 ROS 런타임에 필요한 URDF와 STL 확인
- [o] `src/so_arm101_description` ROS 2 description 패키지 생성
- [o] URDF와 STL 13개 복사
- [o] URDF XML 및 링크 트리 파싱
- [o] URDF의 모든 mesh 참조 확인
- [o] description 패키지 빌드 및 테스트
- [o] `shoulder_pan` 미동작으로 URDF를 Isaac Sim USD로 다시 import
- [o] USD import 옵션의 Base Type을 `Fixed`로 설정
- [o] 각 구동 Joint의 Drive 값 설정: Max Force `10000`, Stiffness `100000`, Damping `1000`

### 확인된 로봇 구조

- 기준 링크: `base_link`
- end-effector 후보 링크: `gripper_frame_link`
- 팔 관절: `shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`
- 그리퍼 관절: `gripper`
- 고정 관절: `gripper_frame_joint`
- URDF 로봇 이름: `so101_new_calib`

### 추가 확인

- [o] Isaac Sim의 `/so_arm101/joint_states`에 포함된 관절 이름과 순서가 URDF와 일치하는지 확인
- [△] Isaac Sim 관절의 회전 방향과 URDF `axis` 방향이 일치하는지 확인
- [△] Isaac Sim의 영점과 URDF의 영점이 일치하는지 확인
- [o] IK 기준 링크를 `base_link`로 적용
- [o] IK 목표 링크를 `gripper_frame_link`로 적용
- [o] 그리퍼 관절을 팔 IK 계산에서 제외
- [o] 시험 목표값이 URDF 관절 제한값 안에 있는지 확인

## 2. 픽셀 좌표와 로봇 좌표 매핑

실제 카메라 캘리브레이션 전까지 시뮬레이션에서 사용할 임시 변환 규칙이 필요하다.

### 결정할 값

- [o] 입력 이미지의 가로·세로 크기: `640 × 480`
- [o] 이미지 좌표 원점과 축 방향: 좌상단 원점, 오른쪽 `+u`, 아래쪽 `+v`
- [△] 로봇 기준 프레임
- [o] 임시 매핑 X 범위: 테이블 중심 기준 `-0.4042539 ~ +0.4042539 m`
- [o] 임시 매핑 Y 범위: 테이블 중심 기준 `-0.5678105 ~ +0.5678105 m`
- [o] 상부 카메라 기준 축 방향 확인: 이미지 위쪽 `World +X`, 이미지 왼쪽 `World +Y`
- [o] 현재 end-effector 기준 상대 XY 이동량으로 임시 매핑 적용
- [o] 초기 시험용 XY 이동량을 축별 최대 `±0.05 m`로 제한
- [△] 고정 작업 높이 Z
- [△] 객체 위 접근 높이
- [△] 픽업을 가정할 때의 하강 거리
- [△] 그리퍼가 아래를 향하도록 하는 고정 orientation
- [△] 이미지 범위 밖 좌표와 로봇 작업영역 밖 좌표의 처리 방식

### bbox 기반 허용 반경

- [△] bbox의 픽셀 크기를 로봇 좌표계 거리로 변환하는 방법
- [△] bbox의 짧은 변에 적용할 허용 반경 비율
- [△] 최소 허용 반경
- [△] 최대 허용 반경

## 3. 액션 서버 이동 및 완료 판정

현재 액션 서버는 실제 관절 도달 여부가 아니라 지정된 시간이 지나면 성공을 반환하므로 실제 `/joint_states` 기반으로 변경해야 한다.

### 결정할 동작

- [o] 현재 `MoveJoints.Goal.duration`을 목표 명령 이동 시간으로 사용
- [o] 목표 관절값 발행 주기를 `50 Hz`로 결정
- [o] 지정된 duration 동안 6축 보간 명령을 반복 발행
- [△] 관절별 위치 허용 오차 결정
- [△] 목표 범위 안에서 유지해야 할 시간 또는 확인 횟수 결정
- [△] JointState 수신 timeout 결정
- [△] 전체 이동 timeout 결정
- [o] feedback 진행률을 보간 단계 기준 `현재 step / 전체 step`으로 계산
- [o] feedback의 `current_state`에 실제 JointState 사용
- [o] result의 `final_state`에 결과 반환 시점의 실제 JointState 사용
- [△] 동시에 여러 Goal이 들어왔을 때 거부·대기·교체 중 하나를 선택

### 실행 구조

- [o] `MultiThreadedExecutor(num_threads=2)`와 분리된 콜백 그룹 적용
- [o] 액션 실행 중에도 별도 스레드에서 JointState 콜백이 처리되는지 확인
- [o] 취소 요청 수락 및 보간 명령 반복 중단 구현
- [△] 취소 시 현재 자세 유지 명령이 필요한지 결정

## 4. 객체 명령 수신과 작업 주기

초기 구현은 Command 노드가 전달한 객체 순서를 그대로 사용한다.

### 입력 검증

- [o] `Detection2DArray`가 비어 있으면 처리하지 않음
- [o] 첫 번째 객체의 `results`가 비어 있으면 처리하지 않음
- [△] confidence `0.85` 미만 객체 필터링
- [△] bbox 크기가 0 또는 음수인 경우
- [△] bbox 중심이 이미지 범위를 벗어난 경우
- [△] 중복 객체 ID 처리
- [△] 메시지 timestamp가 오래된 경우

### 실행 중 새 명령 정책

초기 제안:

- `IDLE` 상태에서 받은 객체 배열만 새 작업으로 시작한다.
- `BUSY` 상태에서 들어오는 탐지 결과는 사용하지 않는다.
- 현재 주기가 성공하면 다시 새 탐지 결과를 기다린다.
- 현재 주기가 실패하면 남은 객체를 폐기하고 새 탐지 결과를 기다린다.

확정할 항목:

- [o] 현재 Goal 실행 중 새 탐지 결과는 보관하지 않고 무시
- [△] 한 주기가 시작된 후 객체 목록을 변경하지 않는다는 정책 확정
- [△] 빈 탐지 결과를 정상 주기로 볼지 입력 오류로 볼지 결정

## 5. 완료 판정의 책임

### 현재 구현 상태

- [o] 액션 클라이언트가 계산한 6축 목표 위치로 이동
- [△] 실제 관절 상태를 이용한 목표 위치 도달 판정
- [△] 객체 중심 허용 반경 안에 들어왔는지 판정
- [△] 목표 위치 도달 후 Z축 하강
- [△] 그리퍼 열기
- [△] 그리퍼 닫기
- [△] 위 과정을 모두 확인한 뒤 객체 작업 완료로 판정

현재는 목표 위치로 이동하는 단계까지만 동작한다. Z축 하강과 그리퍼 열기·닫기가 구현되지 않았기 때문에 객체 작업의 이동완료 판정도 아직 이루어지지 않는다.

### 액션 서버가 책임지는 관절 이동 완료

- 목표 관절값 검증
- Isaac Sim으로 관절 명령 전달
- 실제 관절 상태 확인
- 관절 허용 오차와 timeout 판정
- 이동 성공·실패·취소 결과 반환

### 액션 클라이언트가 책임지는 객체 작업 완료

- 픽셀 좌표 해석 및 로봇 좌표 매핑
- IK 및 FK 계산
- 객체 위 접근 위치 이동
- bbox 기반 XY 허용 반경 확인
- Z축 하강 이동
- 그리퍼 열기
- 그리퍼 닫기
- 모든 단계가 성공했을 때 객체 작업 완료 판정

### 확정할 항목

- [o] 클라이언트 FK 계산에 Isaac Sim의 `/so_arm101/joint_states` 사용
- [o] 클라이언트가 JointState를 직접 구독하여 FK와 IK 시작값에 사용
- [△] 객체 작업 상태 이름과 상태 전이 확정

초기 상태 제안:

```text
IDLE
→ MOVE_ABOVE_OBJECT
→ CHECK_TARGET_REGION
→ MOVE_DOWN
→ OPEN_GRIPPER
→ CLOSE_GRIPPER
→ OBJECT_COMPLETE
```

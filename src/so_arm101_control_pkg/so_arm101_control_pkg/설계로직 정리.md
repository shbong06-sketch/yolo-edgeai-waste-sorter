# SO-ARM101 Isaac Sim 제어 시나리오 설계

## 1. 목표

외부에서 객체의 이미지 평면 좌표를 포함한 이동 명령을 받아 로봇 좌표와
관절 목표값으로 변환하고, ROS 2 액션을 통해 Isaac Sim의 SO-ARM101을
이동시켜 시뮬레이션 결과를 확인한다.

이번 시나리오의 목적은 실제 물체 파지가 아니라 다음 전체 흐름을 검증하는
것이다.

1. 객체 탐지 결과 수신
2. 픽셀 좌표를 로봇 좌표로 변환
3. 목표 자세에 대한 IK 계산
4. Isaac Sim에 관절 이동 명령 전달
5. 이동 상태와 목표 도달 여부 확인
6. 하강 및 그리퍼 열기·닫기 동작 확인

## 2. 전제 및 제한사항

- 상부 카메라의 객체 탐지 상황을 가정한다.
- 초기 단계에서는 실제 카메라 대신 임의의 YOLO 결과 데이터를 사용한다.
- 객체 데이터는 중심 픽셀 좌표, bbox, class와 confidence를 포함한다.
- confidence가 `0.85` 이상인 객체만 작업 대상으로 사용한다.
- 객체는 고정된 작업 평면 위에 있으며 작업 높이 `Z`는 알고 있다고
  가정한다.
- 픽셀 좌표와 로봇 평면 좌표 사이의 매핑은 설정되어 있다고 가정한다.
- 실제 카메라 또는 시뮬레이션 카메라의 캘리브레이션 과정은 추후 추가한다.
- 그리퍼는 항상 아래쪽을 향하는 고정 자세를 사용한다.
- 실제 물체 파지는 수행하지 않는다.
- 객체 위치에서 그리퍼 열기·닫기가 정상적으로 끝나면 가상 픽업이
  성공한 것으로 간주한다.

## 3. 노드별 역할

### 3.1 Command 노드

외부 객체 탐지 결과를 받아 처리할 객체 명령 목록을 생성한다.

- YOLO 형식의 객체 탐지 결과 수신 또는 생성
- confidence가 `0.85` 이상인 객체 필터링
- 객체 명령을 액션 클라이언트 노드에 전달
- 초기 구현에서는 탐지 결과에 포함된 순서를 그대로 유지

Command 노드에서 액션 클라이언트 노드로 명령을 전달하는 ROS 2
인터페이스는 추후 확정한다.

### 3.2 액션 클라이언트 노드

외부 좌표 명령을 로봇이 실행할 수 있는 관절 명령으로 변환하고 객체별
작업 순서를 관리한다.

- 외부 객체 명령 수신
- 객체별 픽셀 좌표 해석
- 픽셀 좌표를 로봇 기준 평면 좌표로 매핑
- 고정 작업 높이와 고정 그리퍼 자세를 적용하여 목표 Pose 생성
- 목표 Pose에 대한 IK 계산
- 액션 서버에 `send_goal`로 관절 이동 Goal 전달
- 액션 피드백, 결과 및 취소 상태 확인
- 현재 관절 상태를 이용한 FK 계산
- end-effector 위치와 객체 중심 사이의 허용 반경 확인
- 객체별 하강, 그리퍼 열기, 그리퍼 닫기 순서 관리
- 현재 주기의 성공 또는 실패 처리

액션 클라이언트는 Isaac Sim에 직접 관절 명령 토픽을 발행하지 않는다.
Isaac Sim에 대한 실제 명령 전달은 액션 서버가 담당한다.

### 3.3 Isaac Sim 제어 노드

ROS 2 액션 서버와 Isaac Sim 사이의 저수준 관절 제어를 담당한다.

- `MoveJoints` 액션 서버 제공
- 액션 클라이언트가 전달한 관절 목표값 검증
- Isaac Sim의 관절 명령 토픽에 목표값 발행
- Isaac Sim의 관절 상태 토픽 구독
- 현재 관절값과 목표 관절값의 오차 확인
- 이동 진행 상태를 액션 피드백으로 전달
- 목표 도달, 제한 시간 초과, 취소 결과 반환
- 취소 시 기존 이동 명령 중단 및 현재 자세 유지

## 4. 전체 데이터 흐름

```text
Mock YOLO Detection
        |
        v
Command 노드
  - confidence 필터링
  - 입력 순서 유지
        |
        v
액션 클라이언트 노드
  - 픽셀 좌표 해석
  - 픽셀 → 로봇 XY 매핑
  - 고정 Z 및 하향 자세 적용
  - IK 계산
        |
        | MoveJoints send_goal
        v
Isaac Sim 제어 노드
  - 관절 명령 발행
  - 관절 상태 감시
        |
        v
Isaac Sim SO-ARM101
        |
        | JointState
        v
이동 피드백 및 성공·실패 판정
```

## 5. 좌표 및 관절 명령 변환

외부 객체 데이터의 중심 좌표는 이미지 픽셀 좌표 `(u, v)`이다.

```text
객체 중심 픽셀 (u, v)
→ 설정된 평면 매핑
→ 로봇 기준 평면 좌표 (x, y)
→ 고정 작업 높이 z 적용
→ 아래쪽을 향하는 고정 orientation 적용
→ 목표 end-effector Pose
→ IK 계산
→ 목표 관절값
→ MoveJoints Goal
```

외부 입력 형식은 추후 변경될 수 있으므로 입력 해석, 좌표 매핑, IK 계산은
서로 분리할 수 있는 구조로 설계한다.

## 6. 객체 처리 순서

초기 구현에서는 Command 노드가 전달한 객체 순서를 변경하지 않고
순차적으로 처리한다.

```text
객체 1 → 객체 2 → 객체 3 → ...
```

경로 최적화는 추후 구현한다. 최적화 단계에서는 다음 기준을 적용할 수
있다.

- 현재 로봇 위치에서 가까운 객체 우선
- 전체 이동 거리 최소화
- confidence 또는 class 우선순위
- 로봇 작업영역과 IK 성공 가능성

실행 중 새 탐지 결과가 들어오면 현재 주기의 객체 목록에는 합치지 않고
다음 주기의 명령으로 보관한다.

## 7. 객체 하나의 작업 절차

객체 하나의 작업은 다음 상태를 순서대로 수행한다.

```text
MOVE_ABOVE_OBJECT
→ CHECK_TARGET_REGION
→ MOVE_DOWN
→ OPEN_GRIPPER
→ CLOSE_GRIPPER
→ OBJECT_COMPLETE
```

세부 절차는 다음과 같다.

1. 객체 중심의 픽셀 좌표를 로봇의 XY 좌표로 변환한다.
2. 고정 작업 높이와 하향 자세를 적용해 객체 위의 접근 Pose를 만든다.
3. 접근 Pose의 IK를 계산한다.
4. 관절 목표값을 `MoveJoints` Goal로 전송한다.
5. 액션 서버가 관절 목표 도달 여부를 확인한다.
6. 현재 관절 상태로 FK를 계산하여 end-effector의 실제 XY 위치를 구한다.
7. end-effector가 객체 중심의 허용 반경 안에 있는지 확인한다.
8. Z축을 소폭 내린 하강 Pose의 IK를 계산한다.
9. 하강 위치로 이동한다.
10. 그리퍼 열기 Goal을 실행하고 관절 도달 상태를 확인한다.
11. 그리퍼 닫기 Goal을 실행하고 관절 도달 상태를 확인한다.
12. 모든 단계가 성공하면 해당 객체 작업을 완료 처리한다.
13. 다음 객체가 있으면 같은 절차를 반복한다.

## 8. 완료 판정

### 8.1 관절 이동 완료

액션 서버는 Isaac Sim에서 받은 현재 관절값과 목표 관절값을 비교한다.

```text
모든 제어 대상 관절에 대해
abs(현재 관절값 - 목표 관절값) <= 관절 허용 오차
```

관절 이동 성공 판정에는 다음 항목이 필요하다.

- 관절별 허용 오차
- 최대 이동 제한 시간
- 목표 범위 내 상태를 유지해야 하는 시간 또는 확인 횟수
- JointState 수신 중단 여부

### 8.2 객체 위치 도달

객체 위치 도달은 XY 평면에서 end-effector와 객체 중심 사이의 거리로
판정한다.

```text
distance = sqrt(
    (end_effector_x - object_x)^2
    + (end_effector_y - object_y)^2
)

distance <= 허용 반경
```

허용 반경은 bbox의 크기를 로봇 좌표계의 거리로 변환한 값으로 계산한다.
초기 규칙은 다음과 같이 설정할 수 있다.

```text
허용 반경 = 로봇 좌표로 변환된 bbox 짧은 변 × 비율
```

- 비율은 `0.5` 이하로 설정하여 허용 영역이 bbox보다 작도록 한다.
- 너무 작거나 큰 판정 범위를 방지하기 위해 최소·최대 반경을 둔다.
- 구체적인 비율과 최소·최대 반경은 시뮬레이션 결과를 보고 결정한다.

### 8.3 객체 작업 완료

다음 조건을 모두 만족해야 객체 하나의 작업 완료로 판정한다.

1. 객체 위 접근 위치 도달
2. bbox 기반 XY 허용 반경 만족
3. Z축 하강 이동 완료
4. 그리퍼 열림 위치 도달
5. 그리퍼 닫힘 위치 도달

단순히 객체 위치로 이동했거나 그리퍼 명령을 발행한 것만으로는 작업
완료로 처리하지 않는다.

## 9. 실패 및 취소 처리

다음 조건 중 하나가 발생하면 현재 객체 작업은 실패한 것으로 처리한다.

- confidence 조건을 만족하는 객체가 없음
- 좌표 입력 또는 bbox 데이터가 유효하지 않음
- 픽셀에서 로봇 좌표로의 변환 실패
- 목표 좌표가 로봇 작업영역 밖에 있음
- IK 해를 찾을 수 없음
- 계산된 관절값이 관절 제한을 초과함
- 액션 Goal이 거부됨
- 제한 시간 안에 관절 목표에 도달하지 못함
- 이동 후 객체 중심의 허용 반경을 만족하지 못함
- Z축 하강 이동 실패
- 그리퍼 열기 또는 닫기 실패
- Isaac Sim의 관절 상태 수신 중단
- 사용자의 취소 요청

실패가 발생했을 때의 처리 정책은 다음과 같다.

```text
현재 액션 Goal 취소
→ Isaac Sim 제어 노드가 이동 명령 중단
→ 현재 주기의 남은 객체 명령 폐기
→ 다음 탐지 주기의 새 명령 대기
```

이전 주기의 실패한 객체를 자동으로 재시도하지 않는다. 동일 객체가 다음
탐지 주기에 다시 포함되면 새로운 명령으로 처리한다.

## 10. 주기 단위 시나리오

```text
1. 새 탐지 결과 목록 수신
2. confidence 0.85 이상 객체 필터링
3. 전달된 순서대로 작업 목록 생성
4. 첫 번째 객체 작업 시작
5. 성공하면 다음 객체 작업
6. 모든 객체가 성공하면 현재 주기 완료
7. 어느 단계에서든 실패하면 현재 주기 중단
8. 현재 Goal 취소 및 남은 객체 폐기
9. 다음 탐지 결과 대기
```

## 11. 추후 구현 또는 결정할 사항

다음 항목은 현재 시나리오의 확장 사항이며 초기 구현 이후 결정한다.

- Command 노드와 액션 클라이언트 노드 사이의 ROS 2 인터페이스
- 외부 객체 명령의 정확한 메시지 형식
- 실제 또는 시뮬레이션 카메라 캘리브레이션
- 픽셀 좌표와 로봇 좌표 사이의 실제 매핑 방식
- FK 및 IK 계산 라이브러리와 로봇 모델
- end-effector 기준 링크 이름
- 고정 작업 높이, 접근 높이 및 하강 거리
- 그리퍼 열림·닫힘 관절값
- 관절별 허용 오차와 이동 제한 시간
- bbox 기반 허용 반경의 비율과 최소·최대값
- 실행 중 들어오는 새 명령의 저장 방식
- 객체 처리 순서와 이동 경로 최적화
- 실제 파지 성공 여부를 판단하는 방법
